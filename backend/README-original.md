# Backend del examen de dispensación (PHP + PostgreSQL)

API REST en PHP 8 puro (sin frameworks ni Composer) sobre PDO y PostgreSQL. Responde JSON y cubre las 11 tablas del esquema: `persona`, `facultad`, `materia`, `carrera`, `postulante`, `coordinador`, `docente`, `se_dicta`, `convocatoria`, `inscripcion` y `rinde`.

## Requisitos
- PHP 8.1 o superior con las extensiones `pdo_pgsql` y `mbstring`
- PostgreSQL con la base cargada (`database/schema.sql` es tu script)

En XAMPP/Laragon activa `pdo_pgsql` en `php.ini` (quita el `;` de `extension=pdo_pgsql` y `extension=pgsql`).

## Puesta en marcha
1. En pgAdmin crea la base `bd_dispe` y ejecuta `database/schema.sql` en ella.
2. Copia `.env.example` como `.env` y completa usuario y contraseña de PostgreSQL.
3. Desde la carpeta del proyecto:
   ```
   php -S localhost:8080 -t public public/index.php
   ```
4. Abre http://localhost:8080/api para ver los recursos disponibles.

Con Apache (XAMPP) apunta el DocumentRoot a la carpeta `public/` (incluye `.htaccess` con `mod_rewrite`).

## Estructura
```
public/index.php        Enrutador y manejo de errores
src/Schema.php          Tablas, columnas y validación (aquí se agregan campos nuevos)
src/CrudController.php  Listar, ver, crear, editar y eliminar (genérico)
src/Reportes.php        Consultas de resumen
src/Database.php        Conexión PDO y transacciones
config/config.php       Lectura del .env
database/schema.sql     Script SQL
```

## Endpoints
Colecciones: `personas`, `facultades`, `materias`, `carreras`, `postulantes`, `coordinadores`, `docentes`, `se-dicta`, `convocatorias`, `inscripciones`, `rinde`.

| Método | Ruta | Acción |
|---|---|---|
| GET | `/api/{recurso}` | Listar. Parámetros: `page`, `limit` (máx. 200), `q` (búsqueda), `sort`, `order=asc/desc` y filtros por columna (`?idCarrera=14`) |
| GET | `/api/{recurso}/{id}` | Ver uno |
| POST | `/api/{recurso}` | Crear |
| PUT/PATCH | `/api/{recurso}/{id}` | Editar (solo envía los campos que cambian) |
| DELETE | `/api/{recurso}/{id}` | Eliminar |

Claves compuestas: `/api/rinde/{idInscripcion}/{idMateria}` y `/api/se-dicta/{idCarrera}/{idMateria}`.

Rutas anidadas (GET): `/api/inscripciones/{id}/notas`, `/api/carreras/{id}/materias`, `/api/carreras/{id}/inscripciones`, `/api/facultades/{id}/carreras`, `/api/facultades/{id}/convocatorias`, `/api/convocatorias/{id}/inscripciones`, `/api/postulantes/{id}/inscripciones`, `/api/materias/{id}/carreras`.

### Postulantes, docentes y coordinadores
Son roles de una persona (su clave es la de `persona`). Al listar o ver, ya incluyen los datos de la persona. Al crear puedes:
- enviar los datos de la persona junto con los del rol: se crean ambos en una sola transacción, o
- enviar `idPostulante` (o `idDocente` / `idCoordinador`) de una persona que ya existe.

```bash
curl -X POST localhost:8080/api/postulantes -H 'Content-Type: application/json' -d '{
  "ci": 9999001, "nombre": "Ana", "paterno": "Quispe", "materno": "Mamani",
  "fecha_nacimiento": "2007-05-10",
  "nacionalidad": "Boliviana", "grado_estudios": "BACHILLER", "estado_postulacion": "EN PROCESO"
}'
```
`DELETE /api/postulantes/{id}` borra solo el rol; con `?con_persona=true` borra también a la persona.

### Reportes (GET)
| Ruta | Contenido |
|---|---|
| `/api/reportes/resultados?idConvocatoria=1&idCarrera=14&estado=ADMITIDO` | Promedio, notas mínima/máxima y posición por carrera |
| `/api/reportes/boletin/{idInscripcion}` | Notas por materia, promedio y costo que corresponde pagar |
| `/api/reportes/inscritos-por-carrera?idConvocatoria=1` | Inscritos por carrera |
| `/api/reportes/ingresos-por-convocatoria` | Inscritos, nacionales/extranjeros y recaudación |
| `/api/reportes/estado-postulantes` | Postulantes por estado |
| `/api/reportes/promedio-por-materia?idConvocatoria=1` | Estadísticas de notas por materia |

El costo se calcula con `costo_nacional` si la nacionalidad del postulante es `Boliviana` (variable `NACIONALIDAD_LOCAL`) y con `costo_extranjero` en caso contrario.

## Respuestas y errores
- `200` correcto, `201` creado, `204` eliminado.
- `400` identificador o parámetro inválido, `404` no encontrado.
- `422` datos inválidos (con el detalle por campo), por ejemplo `{"error":"Datos inválidos.","detalles":{"nota":"Debe ser <= 100."}}`.
- `409` valor duplicado (CI, clave) o eliminación bloqueada por registros relacionados.
- Los números (`nota`, costos) salen como números JSON y las fechas como `AAAA-MM-DD`.

## Notas
- Tus claves primarias son `INTEGER` sin autoincremento. Cuando no envías el id, el backend usa el siguiente disponible (`MAX + 1`) bajo bloqueo de tabla. Si prefieres que PostgreSQL los genere, cambia la columna a `GENERATED BY DEFAULT AS IDENTITY` y el backend seguirá funcionando si envías el id o no.
- Si defines `API_KEY` en `.env`, cada petición debe incluir el encabezado `X-API-Key`. No hay login de usuarios; si lo necesitas, se agrega como una capa aparte.
- La nota admite valores de 0 a 100 (en tus datos van de 30 a 100). Cámbialo en `src/Schema.php` si tu escala es otra.
